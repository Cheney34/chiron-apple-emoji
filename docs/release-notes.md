# Chiron × Apple Emoji 6.6

**这一版只改了一件事：把 emoji 字体从 3 个档位补回 5 个档位。**

6.5.2 把挂载链路整套修好了，但装上看到的仍然是安卓那张扁平脸。真凶不在挂载，在字体本身。

## 为什么明明挂上了，画出来还是安卓的

CBDT/CBLC 是**定点位图**字体。系统按实际渲染的像素大小去挑 strike（位图档位）：

| 版本 | `STRIKES` | 位图实际像素 |
|---|---|---|
| 5.0（你一直在用的那版） | 32,45,60,82,128 | 38 / 53 / 70 / 96 / 150 px |
| 6.3 – 6.5.2 | 32,45,60 | 38 / 53 / 70 px |

6.3 重写模块时为了把包体从 180 MB 压到 57 MB，砍掉了 82 和 128 两档。

后果是：小字号落在 38/53/70 里，正常显示苹果字形；一旦界面把 emoji 放大到 96 px 或
150 px（emoji 键盘预览、表情详情页、通知大图标、微信大表情、部分 App 的自绘标题），
字体里没有对应档位，FreeType 返回 size 不匹配，Minikin 判定「这个字体画不出这个字号」，
**整段回退到系统自带的 NotoColorEmoji** —— 也就是 AOSP 风格。

所以症状一直很迷惑：

- 小字号像 iOS，一放大就变安卓；
- 同一个字体，有的 App 对、有的 App 不对；
- `mount` 看是全挂上了，`stat` 也显示 60 MB 是模块的字体，但画面就是不对。

## 改了什么

- `system/fonts/NotoColorEmoji.ttf` 用 `STRIKES=32,45,60,82,128` 重新构建，
  5 档真彩 RGBA，位图 38/53/70/96/150 px。`bitDepth` / `flags` / `hori.ascender` /
  `descender` / `widthMax` 与 5.0 逐项对齐，体积 189.7 MiB。
- 字形 4006 个（5.0 是 3842），连字 3730 条，含 Unicode 17.0 全部新增表情
  （Distorted Face、Fight Cloud、Hairy Creature、Bald、Apple Core、Treasure Chest…）。
- 安装时自检档位：字体小于 130 MB 直接警告「这是旧的三档包」。
- 模块详情页「执行」的诊断里会写明当前是 5 档还是 3 档。
- 挂载链路与 6.5.2 完全一致，没有改动。正文字体也没动。

## 装

KSU Manager → 模块 → 从本地安装 → 选本页的 zip → **重启**（必须重启，
`post-fs-data` 只在开机早期跑）。

装完想确认：模块详情页点「执行」，看诊断里的「档位」那行是不是写着
`5 档（38/53/70/96/150 px）—— 正常`。
