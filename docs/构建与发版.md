# 构建与发版

从源码到 `v6.2` 三个产物的完整流程。所有命令都在仓库根目录执行。

## 0. 环境

| 需要 | 版本 | 用途 |
|---|---|---|
| Python | ≥ 3.9 | 字体处理、打包 MTZ |
| `fonttools` `pillow` | 最新 | `pip install fonttools pillow` |
| zip | 任意 | 打 Root 模块 |
| JDK 17 + Android SDK | — | 只有本地构建 LSPosed 才需要，**推荐交给 CI** |

`chiron-font/build_v6.py` 里的默认路径是作者原机器的绝对路径，**别照抄**，一律用命令行参数覆盖。

## 1. 素材

Apple emoji 位图与元数据，一次准备：

```bash
npm pack emoji-datasource-apple@16.0.0
tar -xf emoji-datasource-apple-16.0.0.tgz
# 位图：package/img/apple/64（160px 目录也可以，脚本会自己缩放）
# 元数据：emoji-font/emoji-data.json 已随仓库提供
```

Chiron GoRound TC VF 与 Merriweather（300/400/800 三份实例）自备，`chiron-font/README.md` 里有来源。

## 2. 三个产物

### 2.1 emoji 字体（两条通道档位不同）

```bash
cd emoji-font

# Root：五档真彩，约 188 MB
IMGDIR=../package/img/apple/64 JSONF=emoji-data.json \
OUT=../build/emoji/root.ttf python3 build17.py

# MTZ：双档真彩，约 55–60 MB
STRIKES=45,96 IMGDIR=../package/img/apple/64 JSONF=emoji-data.json \
OUT=../build/emoji/mtz.ttf python3 build17.py
```

跑完检查一下 `art:` 的数字，应该在 3800 上下；明显偏少说明素材目录挑错了。

### 2.2 MTZ

```bash
cd chiron-font
python3 build_v6.py \
    --src-font ../build/mtz/fonts/Roboto-Regular.ttf \
    --emoji    ../build/emoji/mtz.ttf \
    --version  6.2 \
    --out      ../Chiron-Emoji-v6.2-MTZ.mtz
```

脚本会先打印两段校验结果再打包。**看到 `!! 规格不合格，拒绝打包` 就停下来**，按提示回去改 `STRIKES` 或重跑 `fix_metrics.py`，不要加 `--force` 绕过——那正是 v6.2 出问题的路径。

### 2.3 Root 模块

```bash
cd magisk-module
mkdir -p system/fonts
cp ../build/emoji/root.ttf system/fonts/NotoColorEmoji.ttf
zip -r ../Chiron-Emoji-v6.2-Root.zip . -x '*/.git*'
```

### 2.4 LSPosed APK

不用本地搭 Android SDK。推到 GitHub 后：**Actions → 构建 LSPosed 模块 → Run workflow**，几分钟后 `lsposed-apk` artifact 里就有 `AppleEmoji_Sogou_LSPosed_v1.7.apk`。

## 3. 发版前自查

```bash
python3 - <<'PY'
import zipfile, hashlib, os
for f in ["Chiron-Emoji-v6.2-MTZ.mtz", "Chiron-Emoji-v6.2-Root.zip"]:
    if not os.path.exists(f): print("缺", f); continue
    print(f, os.path.getsize(f), hashlib.sha256(open(f,'rb').read()).hexdigest()[:16])
    with zipfile.ZipFile(f) as z: print("  ", len(z.namelist()), "entries")
PY
```

| 检查 | 期望 |
|---|---|
| MTZ 里 `fonts/NotoColorEmoji.ttf` | 50–60 MB（真彩双档），不是 18 MB |
| MTZ `description.xml` 的 `<version>` | 6.2，与文件名一致 |
| Root zip 里 `uninstall.sh`、`NOTICE.txt` | 都在 |
| `module.prop` | `version=6.2`、`versionCode=9` |
| 构建日志尾行 | `mtz -> ... version=6.2`，没有 `!! 规格不合格` |

## 4. 打 tag 与发 Release

```bash
git add -A
git commit -m "release: 6.2 —— 统一版本号、MTZ 规格校验、构建脚本修正"
git push origin main
git tag -a v6.2 -m "v6.2"
git push origin v6.2
```

推 tag 会触发 CI，自动构建 APK 并创建 Release，**APK 会作为附件自动挂上**。剩下两个包手动补：

Releases → 编辑 `v6.2` → 拖入 `Chiron-Emoji-v6.2-MTZ.mtz` 与 `Chiron-Emoji-v6.2-Root.zip` → 正文用下面这份。

```markdown
## 本次更新

- 统一版本号：项目、Root 模块、MTZ 全部对齐到 6.2，此前 Root 是 v5.0、MTZ 是 6.2，同一个名字下两种规格
- MTZ 换回真彩 emoji：v6.2 里塞的是 256 色量化的单档位图（脸部渐变出现色阶、图形只占格子 80%），本版改为双档真彩，字宽归一到 1.172 em
- 构建入口加校验：打包前检查位图档数 / 色彩模式 / advance width / cmap / GSUB ccmp / 正文字体垂直度量，不合格直接拒绝出包
- Root 模块安全修复（5.1 起）：覆盖前先备份、卸载自动还原 GMS 字体服务与主题 emoji、overlay 兜底改为手动开启并带开机死循环熔断、安装器自动识别 Magisk / KernelSU / APatch，新增 `uninstall.sh`
- 搜狗 LSPosed 模块 1.7：在 `File.list()` 与 `ExpressionUtil.u()` 两处拦截，真正移除「组合」「拼装」分组，卸载即恢复

## 附件

仓库只含源码与构建脚本，字体成品与第三方美术资源不随仓库分发。Apple emoji 位图版权归 Apple Inc.，本项目未获再分发授权，请自行获取素材并按本机使用处理，详见 [THIRD-PARTY.md](../THIRD-PARTY.md)。
```

## 5. 真机验收

按顺序，每条都能从日志验证：

1. **MTZ**：主题商店装上后，设置里能看到 `Chiron Emoji` 6.2；微信聊天框里 emoji 边缘不发灰
2. **Root 模块**：`cat /data/adb/chiron_apple_emoji/post-fs.log`，应有 `stashed /data/fonts` 与 `bind OK`
3. **overlay 默认关**：没有 `enable_overlay` 文件时，日志是 `overlay fallback is OFF by default`
4. **可卸载**：卸载后 `pm list packages -d` 里不见 GMS 两个字体组件，`/data/adb/chiron_apple_emoji/disabled.list.done` 存在
5. **主题 emoji 还原**：`/data/system/theme/fonts/` 里的 emoji 与 `backup/…/theme-*` 的 sha256 一致
